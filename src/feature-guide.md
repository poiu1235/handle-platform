# 管理端功能与操作说明

> 覆盖范围：`src/pages/Hello.jsx`（管理端首页，路由 `/app`）与
> `src/pages/BalanceImport.jsx`（余额批量导入页，路由 `/app/balance-import`），
> 样式见 `src/index.css`。已对照 7 张截图（首页1/首页2/操作入口/添加/修改/清零/批量添加）核对。

---

## 〇、两页关系与数据说明

- **管理端首页**是资产总览：三个分类标签「余额 / 会籍 / 优惠券」，核心是可滑动操作的余额卡片列表。
- **余额批量导入页**从首页右下角「+」→「批量增加」进入，用于把表格里两列数据一次性粘贴导入。
- **只有「余额」接了真实后端**（`/api/balances`，经 Cloudflare 中间层转发 Supabase，RLS 保护数据归属）；
  「会籍 / 优惠券」目前是页面里写死的演示数据，**只读**——没有 FAB、没有滑动、不能增删改。
- 后端对余额是**按名字 upsert**：同名记录覆盖余额，新名字新增记录——所以所有新增入口都有重名覆盖的语义。

## 一、管理端首页（Hello）

### 1. 顶部

- 眉题 `ASSETS OVERVIEW` + 大标题「Handle 数据管理端」。
- 右上角「退出登录」文字按钮：清除登录态并回登录页。
- 标题下有一行登录态指示（状态圆点 + 文案）：
  - 验证中：「正在验证登录态…」
  - 正常：显示当前登录邮箱
  - 失败：「接口调用失败：具体原因」

### 2. 分类标签

- 三个胶囊标签：余额 / 会籍 / 优惠券，各自右侧带**条数徽标**。
- 选中态为深绿底白字，默认选中「余额」。
- 余额的条数 = 当前接口返回的记录条数，**会随下方「展示 0 余额」开关变化**
  （截图里开关关时是「余额 5」、开时是「余额 20」就是这个原因）。

### 3. 排序（三个按钮）

- 「按更新时间 / 按金额 / 按名称」，默认**按更新时间降序**（最新在前）。
- 点**未选中**的按钮：切换到该维度，并默认降序；点**已选中**的按钮：降序 ⇄ 升序互换。
- 当前维度按钮文字后带方向箭头：`↓` 降序、`↑` 升序。
- 金额降序 = 余额多的在前（截图首页 2）；名称排序按**中文拼音**（Intl.Collator，环境不支持时退回 ASCII 排序）。
- **特殊规则：余额为 0 的记录永远沉底**，不参与主排序，只在 0 余额分组内部按所选规则排。

### 4. 「展示余额为0的小程序列表」开关（仅余额标签下显示）

- iOS 风格滑动开关，**默认关闭**。
- 每次拨动都会**重新请求接口**（带 `includeZero` 参数），不是本地过滤。
- 关：列表只有余额 > 0 的记录；开：0 余额记录也加载，显示为**灰色卡片**并沉在列表底部。

### 5. 余额卡片列表

**三种列表状态**

- 加载中：状态行「正在加载余额…」
- 加载失败：红色错误提示条，附具体原因
- 空数据：提示条「还没有余额数据，去批量导入余额页面提交一批，或者用下方的'+'新增一条」，
  其中「批量导入余额」是可点链接，直达导入页。

**卡片外观**

- 每条记录一张彩色卡片：颜色由记录 id 哈希后从 16 色暖色盘（橙/黄/杏色系）里取，
  **同一条记录永远同一颜色**，刷新、重新加载都不会跳色。
- 余额为 0：固定灰色卡片（`#dfe1d7`），名称和金额文字变淡。
- 卡片左侧名称前有 ◆ 小菱形标记；右侧金额加粗（带千分位）+ 单位「元」。

**折叠态（默认）与展开态**

- 折叠时所有卡片像「一沓卡包」：相邻卡片用 -18px 负 margin 叠压，前面的卡片盖住后面卡片的下边缘、
  露出后一张一点顶边（截图首页 1 / 首页 2 的层叠效果）。折叠卡片只显示名称 + 金额。
- **单击卡片展开**：该卡片跳到最上层、上下留出正常间距、多显示一行「YYYY年MM月DD日更新」，
  并自动平滑滚动到屏幕中央（"从卡包里抽出来"的效果）。
- **同一时间只展开一张**：点另一张会自动折叠当前这张；再点已展开的卡片收起。

### 6. 展开后的滑动操作（核心交互）

前提：**必须先点开（展开）一张卡片**，折叠态的卡片不响应拖动。
触屏滑动、PC 鼠标按住拖动都可以（Pointer Events 统一实现）。

**① 左滑（向左拖）→ 右侧露出「修改」「删除」（截图 修改.jpg）**

- 「修改」墨绿色、「删除」砖红色，各占固定宽度，展开宽度封顶、不能越滑越深。
- 松手判定：滑出超过 40px、或快速向左一甩（即使距离不足）→ 自动吸附展开；否则弹回原位。
- 点「修改」→ 打开修改弹窗（预填当前值）；点「删除」→ 打开删除确认弹窗；点卡片本体 → 收回按钮。

**② 右滑（向右拖）→ 左侧露出「清零」（截图 清零.jpg），仅余额 > 0 的卡片可用**

- 0 余额卡片右滑被完全禁用（已经为 0，无意义）。
- **浅滑**（滑出超过 40px 但不到卡片一半）：松手吸附露出琥珀色「清零」按钮，需再点按钮确认执行。
- **深滑**（拖过卡片宽度一半）：左侧面板变成填充态大号「清零」，松手**直接执行，无需再点**。
- **快速向右一甩**（距离很短但速度快）：同样直接执行清零。
- 执行瞬间卡片像聊天软件划掉会话一样**整体向右飞出屏幕**消失，随后才发请求（无二次确认弹窗）。

**③ 单击展开 / 收起**

- 见第 5 节；拖动过的手势不会被误判为点击（位移 > 4px 即视为拖动，不触发点击）。

### 7. 清零 / 删除 / 修改 三者的语义区别（重要）

| 操作 | 数据库行为 | 是否保留记录 | 有无确认 |
| --- | --- | --- | --- |
| 清零 | 余额改为 0，更新时间记为本次操作时刻 | **保留** | 无（深滑/快甩即执行） |
| 删除 | 整条记录彻底移除，之后查询不到 | **不保留** | 有自定义确认弹窗 |
| 修改 | 改名/改余额，更新时间记为保存时刻 | 保留 | 无（弹窗本身可取消） |

- **清零后**：若「展示 0 余额」开关是关的，该卡片立刻从列表消失（看起来像没了，但库里还在）；
  开关开着则卡片留在列表里变灰、沉底。请求失败会提示「清零失败」并自动重新加载还原。
- **删除确认弹窗**文案明确区分两者：「删除后会从数据库中彻底移除，之后查询不到；
  如果只是想把余额归零、以后还想保留这条记录，请用清零」。点「确定删除」本地先移除（乐观更新），
  后台失败会报错并重新加载列表。
- 删除弹窗是自定义的红色危险样式，与系统 `window.confirm` 区分。

### 8. 右下角「+」浮动按钮（FAB，仅余额标签下显示）

- 深色圆形「+」悬浮在列表底部水平居中位置。
- **点一下展开**：弹出全屏半透明遮罩 + 两个白色胶囊菜单项「批量增加」「增加一条」（截图 操作入口.jpg），
  同时「+」变为「×」。
- 「批量增加」→ 跳转余额批量导入页；「增加一条」→ 打开新增弹窗。
- 点遮罩或再点「×」收起菜单。

### 9. 新增 / 修改弹窗（共用一套表单，截图 添加.jpg 为新增态）

- **新增模式**：标题「新增余额记录」，顶部米黄色提示条：
  「小程序名如果和已有记录重名，会直接覆盖那条记录、更新它的余额，不会新建一条重复的」。
- **修改模式**：标题「修改余额记录」，无提示条，两个输入框预填当前名称和余额。
- 输入框：小程序名（占位「如：肯德基」，弹窗打开自动聚焦）、余额（占位「如：50」，手机上调起数字键盘）。
- 校验：名称非空（去首尾空格）**且** 金额非空且是合法数字，「保存」才可点。
- 提交中：保存按钮显示「保存中…」，取消/保存均禁用。
- 取消：点按钮或点遮罩关闭。
- 成功：弹窗关闭，列表自动刷新（重名覆盖/修改结果立即可见）。
- 失败：弹窗内显示红色错误提示，弹窗不关、已填内容保留，可改后重试。

## 二、余额批量导入页（BalanceImport）

### 1. 页面结构

- 眉题 `BALANCE IMPORT` + 标题「余额批量导入」；右上角「返回管理端」「退出登录」两个文字按钮。
- 标题下是操作说明文案；主体为大号粘贴文本框（约 10 行高），下方「提交」按钮（截图 批量添加.jpg）。

### 2. 操作流程

1. 在 Excel / 飞书表格等里**复制两列（小程序名、余额）**，直接粘贴进文本框，每行一条。
2. 粘贴后文本框下方**实时出现「解析预览」区**：解析出的条数（N 条）、逐行错误提示、
   以及「小程序名 / 余额」表格预览（金额带千分位）。
3. 检查预览无误后点「提交」；提交中按钮显示「提交中…」并禁用。
4. 成功：显示提示「已提交 N 条，相同小程序名已覆盖，新名称已新增」，**文本框自动清空**。
   失败：红色错误提示，文本框内容保留，可直接改后重试。

### 3. 解析规则细节

- **分隔符兼容**：Tab（从表格直接复制的默认格式）、英文逗号、连续空格均可；
  每行取第 1 列当名称、第 2 列当金额，多出来的列忽略。
- 金额里的**千分位逗号会被剔除**再转数字（`1,300` 合法）。
- 空行自动跳过。
- **逐行报错**（格式：第 N 行：原因 —「原文」），三类原因：
  - 缺少字段（需要 名称 和 余额 两列）
  - 小程序名为空
  - 余额「xx」不是有效数字
- **表头特例**：第一行如果金额解析不出数字，按「表头行」处理**直接跳过不报错**
  （示例占位文案第一行就是表头「小程序名 余额」）。
- **同批次重名**：保留**最后一条**（后面的覆盖前面的），预览标题旁注明「同批次内有重名，已保留最后一条」。
- 「提交」按钮可用条件：解析出 ≥1 条有效记录 **且** 零错误 **且** 不在提交中（文本框为空时置灰）。
- **提交语义（upsert）**：与库里已有记录同名的 → 覆盖其余额；新名称 → 新增一条；
  整批共用同一个提交时刻作为更新时间（预览里看到的条数就是最终提交条数）。

## 三、边界与注意事项汇总

1. 滑动操作只对「余额」标签下**已展开**的卡片生效；会籍/优惠券是演示数据，无任何写操作。
2. 深滑/快甩清零**没有确认弹窗**，注意误操作——但记录未删，随时可用「修改」把金额改回来。
3. 「余额 N」徽标数随 0 余额开关变化；0 余额记录默认不加载，开关打开才出现在列表（灰色、沉底）。
4. 删除是唯一不可逆操作（有确认弹窗兜底）；清零可逆。
5. 一切新增入口（单条新增、批量导入）都是同名覆盖语义，不会产生重名重复记录。
6. 列表改动成功后都会自动重新拉取接口，多端数据保持一致；失败时本地乐观更新会回滚重载。
