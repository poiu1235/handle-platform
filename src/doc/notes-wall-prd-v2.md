# 便签墙 · PRD（v2）

> 页面名：便签墙（Notes Wall）· 路由 `/app/notes`
> 一句话：像贴便利贴一样把备忘贴上一面「墙」，每张贴纸可挂一个**精确到分钟**的提醒，
> 可勾选完成后划线保留；数据存云端，同账号多设备打开看到同一面墙——**「便利贴 + 日程提醒」**。
> 结构与命名对照 `lifestyle-cardpack-prd-v3.md` / `cards-db.md`；视觉规范完全沿用
> `design-language.md`（token、字体、圆角、z-index 表）。
> 本版（v2）按「推翻重新设计」流程产出：从需求重新推导，再与 v1
> （`notes-wall-prd-v1_bak.md`）对比取优，差异清单见 〇.2。
> **v2.1 修订（2026-09-12）**：新增便签双形态（提醒/普通）、四动作直达
> （完成/Pin/修改/删除）、Pin 钉住、状态模型（正常/完成/过期）——见 D9–D12。
> **v2.2 修订（2026-09-12）**：新增 D13「开始时间」——便签的关注时间：提醒便签 =
> 闹钟时刻，普通便签 = 创建时刻；界面样式草样见仓库根 `notes-wall-mockup.html`。
> **v2.3 修订（2026-09-12，交互改版）**：流式顺序网格（拖拽=调序）、7 天窗口
> （D15）、便签三分 提醒/备忘/灵感（D14）、已完成默认隐藏（D2）、过期不置灰
> （D16）、全天提醒（D17）、重复扩为天/周/月/年/固定N天（D18）、移除快捷时间
> chips（D19）。样式草样同步更新。
> **v2.4 修订（2026-09-12，融入标签页 · Keep 式记录网格）**：便签成为 Hello 分类
> 标签一员（D20），「同一网格 + 类型区分 + 顶部筛选」；**颜色改为派生**（D21，
> 任务黄系紧迫度加深、点子白卡，取色器与 color 字段移除）；任务卡左上角复选框
> （D12 改）；已完成改为网格底部「已完成」折叠区、不再默认隐藏（D2 改）。
> **废止**：拖拽调序（D4 改自动排布）、7 天窗口（D15 改全量展示+颜色编码）、
> 手机今日视图（D3）、hover 工具条与长按面板、胶带/磁贴拟物。
> **v2.5 修订（2026-09-12，统一距离排序）**：任务与点子的时间语义相反（到期正序 vs
> 创建倒序），混排不能按时间戳本身排序——改用统一指标 **`abs(距今天天数)` 升序**
> （D4/D22）；距离同时驱动视觉衰减，越靠下越淡：**往下翻 = 离当下越远**，
> 不管下方是旧点子还是远期任务。

### 〇.1 决策表（2026-09-06，与用户确认）

| # | 决策点 | 裁定 |

| D2 | 完成态（v2.4 改） | `status = active / done`；完成后**不消失**——自动折叠进网格底部可展开的「已完成」区（划线置灰、可回看，对齐平台「历史数据保留」调性）；「清除已完成」保留，跳过 pinned |
| D3 | 手机形态（v2.4 废止原案） | 便签融入标签页后**不再有独立手机首屏**：手机与桌面同一网格（列数自适应）；「今日」紧迫感由排序靠前 + 颜色加深承担，不再单独分组 |
| D4 | 排列顺序（v2.5 改） | **自动排布，无拖拽**：pinned → **统一距离指标 `abs(距今天天数)` 升序** → 已完成入折叠区。任务取 `remind_at`（全天按当天 00:00）、点子与无提醒任务取 `created_at`。**为什么**：任务按到期正序、点子按创建倒序，两条时间轴方向相反，按时间戳混排无解；距离指标让「往下翻 = 离当下越远」有唯一语义。`sort_order` 与 reorder 接口维持移除 |
| D5 | 多端同步 | **进站先渲缓存快照再全量拉取 + 可见时 45s 轮询 + 操作乐观更新**，不引入 Realtime 长连接；冲突 LWW；新增**同步状态指示**，让「多端同步」可感知 |
| D6 | 提醒规则 | **一次性 + 简单重复（每天/每周）**；到点未确认保持醒目态，**确认时**推进下一次 |
| D7 | 编辑形态 | **弹窗编辑**（新建 = 编辑复用），不做双击就地编辑 |
| D8 | 完成与提醒交叉 | **完成优先于重复**：便签被勾完成后不再提醒、不再推进；完成隐含「确认」当次到点 |
| D9 | 形态与字段（v2.4 改） | 原「双形态全派生、不设 type 字段」演进为 D14 的 `kind` 方案（用户视角两类需要显式落库）；保留其原则：**能派生的绝不重复存储**——「带提醒/纯备忘」仍由 remind_at 派生，无独立字段 |
| D10 | Pin 钉住（v2.4 改） | `pinned` 落库；语义三件事：① 排序**置顶**（D4 规则首位）② 标题行一枚 14px 图钉小图标（拟物表达「钉住」）③「清除已完成」跳过 pinned——钉住 = 我要一直看到它 |
| D11 | 状态模型 | 用户可见状态三档：**正常 / 完成 / 过期**（过期仅提醒便签）。落库仍只有 `active / done`，**过期是派生态不落库**（时间自己会流动，不写库的状态机才不会烂）；两段处理：该轮未确认时强提醒（响铃/闪烁/错过条），确认后警示消、过期标签留到解决（完成/改期/关提醒/删除） |
| D12 | 动作直达（v2.4 改） | **任务便签左上角常驻复选框 ☐/☑**——一键完成/恢复（点子便签无复选框）；点击卡片 = 折叠/展开（复用 cards 交互，同时只一张展开）；编辑/钉住/删除在展开态动作行与编辑弹窗内。v2.1 的 hover 迷你工具条与长按面板废止 |
| D13 | 开始时间（v2.4 改） | 提醒便签 = `remind_at`（闹钟/全天即开始）；备忘便签 = 创建时刻；**点子无开始时间**。卡片上**只有带提醒的便签显示时间胶囊**，其余一律不显示时间；列表排序按开始时间（v2.4 起无窗口裁剪，全量展示） |
| D14 | 类型两类（v2.4 命名对齐） | 用户视角两类：**任务**（「明天提醒我买牛奶」「荔枝成熟了给爸妈买一些」——可带提醒，左上角复选框）与**点子**（「我有一个好点子」，白卡、无提醒、默认展开摘要）。落库 `kind = task / idea`：task 内「带提醒/纯备忘」由 remind_at 派生；点子**禁止带提醒**（CHECK 兜底）、无开始时间、永不过期 |
| D15 | 7 天窗口（v2.4 废止） | 窗口裁剪废止，**全量展示**（用户裁定：展示所有便利贴、默认混排）；紧迫感不再靠隐藏窗口外内容，改由**颜色编码**承担（D21）——样式随紧迫度变化，与余额表「样式随数值变化」同构 |
| D16 | 过期视觉（v2.3 改） | 过期便签**不划线、不置灰、不沉底**——保持原色原位，仅显示「已到点 / 已过期」徽标；该轮未确认仍走强提醒（闪烁 + 错过条） |
| D17 | 全天提醒（v2.3 新） | 提醒模式二选一：**指定时间**（日期 + 时间，分钟精度）/ **全天**（只选日期）。全天 = 当天**任何时刻进入页面都要提醒**（当日首次进站/轮询/巡检命中即触发，当日仅一次）；过期从次日 00:00 起算 |
| D18 | 重复规则（v2.3 扩） | `不重复 / 每天 / 每周 / 每月 / 每年 / 每隔 N 天`（N：1–365 步进器）；月末钳制（1月31 → 2月28/29）、闰年 2/29 → 2/28；advance() 扩展并全量测试 |

### 〇.2 与 v1 的对比取优

**保留（重新推导后结论不变）**：轮询同步 + LWW（D5）、自由拖拽网格吸附 + 6 列固定
坐标系（D4）、提醒调度器架构（setTimeout 精确唤醒 + 30s 兜底 + 回焦巡检）、错过补列
不补铃、确认后推进重复、6 色拟物便签 + 哈希倾斜不落库、diff-only PATCH、弹窗编辑、
JIT 申请通知权限、多标签页去重。

**新增 / 修正**：

1. **完成态 status**（v1 无）——含视觉、过滤片、批量清除、与重复提醒的交叉语义（D2/D8）。
2. **手机今日视图**（v1 手机 = 整墙横滚，横向找便签成本高）——列表分组纯函数与桌面
   「待办」过滤片同源，口径永不漂移。
3. **同步状态指示点 + localStorage 快照秒开**——「多端同步」从后台行为变成可感知卖点。
4. **`notesDomain` 从 `src/lib` 提升到 `shared/`**——V2 的 Cron Worker 必须复用同一个
   `advance()`，否则两端推进语义漂移。
5. **V2 扫描索引方向修正**：cron 按**时刻**全表扫（`remind_at` 部分索引），不是 v1 的
   `(user_id, remind_at)`——Worker 不按用户扫。
6. **新增 `last_fired_at` 字段**（V1 即落库、前端触发时即写）——V2 Worker 幂等去重靠它，
   上线时零迁移。
7. **附录 A 明确 V2 载体：独立 Cron Worker**——Cloudflare Pages Functions 不支持
   cron triggers，不能给本项目 wrangler.toml 加 trigger。

## 一、产品概念与信息架构

- 核心实体只有一张便签——本质上和余额记录一样是**一条记录**：同一套「展示随数据
  变化、点开就能改」的逻辑。动词七个：**贴**（新建）、**写**（编辑）、**勾**（完成/
  恢复）、**撕**（删除）、**钉**（Pin 置顶）、**设**（提醒）、**筛**（全部/任务/点子）。
- **融入 Hello 分类标签（D20，v2.4）**：`Hello.jsx` 的 `TABS` 追加
  `{ key: 'notes', label: '便签' }`（现有 余额 / 会员 / 优惠券 之后）。独立路由
  `/app/notes` 与「← 返回」随之废止；便签 store 在标签**首次激活时懒加载初始化**
  （对齐 cards 面板挂载策略），数据仍走 `/api/notes`。
- **用户视角两类（D14 命名对齐）**：**任务**（「明天提醒我买牛奶」「今天 15:00 提醒我
  给海伦打电话」「荔枝成熟了给爸妈买一些」——可带提醒，左上角复选框）与
  **点子**（「我有一个好点子：做一个便利贴墙」——白卡、无提醒、默认展开）。
  工程上 `kind = task / idea`，task 内「带提醒 / 纯备忘」由 remind_at 派生；
  状态三档：正常 / 过期（仅带提醒的任务）/ 完成（D11）。
- FAB 随标签切换：便签标签下弹「记任务 / 记点子」（其余标签保持原菜单）。

## 二、页面布局

便签与余额/会员共用 Hello 骨架（深蓝 hero / 分类标签 / FAB / 弹窗层级 / `--bd-col`
560px 内容列 / notice 形态），本节只描述**便签标签激活时**的内容区。

1. **筛选行**：分段胶囊「全部 / 任务 / 点子」（默认全部混排，计数徽章，复用 cards
   分段控件，D20）+ 右侧「清除已完成」文字链（已完成区非空才出现，二次确认，
   跳过 pinned，D10）。
2. **错过提醒条**（条件渲染）：进站/轮询发现「到点未确认」的提醒便签时，内容区
   顶部品牌浅蓝 notice「有 N 条到点的提醒」→ 展开列出，逐条或「全部知道了」确认。
3. **便签网格**（Google Keep 式瀑布流）：`--bd-col` 列内 CSS multi-column
   （桌面 3 列 / 窄屏 2 列，列距 12px），**默认全部混排**（D20）：
   - 排序规则（自动，无拖拽，D4）：pinned → 统一距离指标 `abs(距今天天数)` 升序
     （任务 = remind_at；点子/无提醒任务 = created_at；同距离按精确时刻贴近今天
     者在前）；
   - **已完成区**：主流网格之后一条折叠栏「已完成 N ▾」，点击展开为同样瀑布流
     （划线置灰卡，D2），再点收起；
   - 空态：灰字「还没有便签，点右下角 + 记一条」。
4. **便签卡片**：
   - **折叠态（任务）**：复选框 ☐ + 正文首行当标题（nowrap+ellipsis）+
     时间胶囊（仅带提醒的，D13）+ 弱化相对时间；点击展开；
   - **折叠态（点子）**：默认**展开摘要**（正文 4 行截断），无复选框；
   - **展开态**：全文 + meta 行 + 动作行「标记完成/恢复（仅任务） · 钉住/取消 ·
     编辑 · 删除」；同时只一张展开、跳 z 1000、`scrollIntoView({ block: 'center' })`、
     再点收起（复用 cards 展开行为）。
5. **FAB**：便签标签下弹两项菜单「记任务 / 记点子」（错峰弹入，同 FAB 菜单样式）
   → 打开编辑弹窗并预选类型。
6. **弹窗层**（z-index ≥1020）：便签编辑弹窗、删除确认弹窗、提醒卡（5.1）。

## 三、便签视觉规格（v2.4，颜色即数据）

- **颜色 = 派生，不手选（D21）**——「样式随数值变化」的直接复用：
  - **任务（黄系，底色随紧迫度加深）**：常规 `#FFF6A3` → 距开始 ≤ 24h（含全天当天）
    深黄 `#FFE388` → **已过期未处理** 浅橙红 `#FFC9A3`；文字一律 `--au-text`；
  - **点子（白卡）**：`--au-card #FFFFFF` + 1px `--au-border` 描边（黄系靠色块、
    白卡靠描边分层，符合设计语言 3.6）；
  - 色档映射表放 `shared/notesConfig.js`，测试覆盖。
- **微倾斜**：`hash(id) % 5` 确定性映射到 `-2°, -1°, 0°, 1°, 2°`——**不落库**，
  多端渲染一致；这是仅存的便利贴拟物（胶带/磁贴装饰废止——记录网格里它们是噪音）。
- **阴影**：复用余额折叠卡投影 `0 3px 8px rgba(1,15,28,0.10)`，展开态加深为
  `0 10px 26px rgba(1,15,28,0.16)`。
- **距离衰减（D22，v2.5）**：`abs(距今天天数)` 分五档（≤1 / ≤3 / ≤7 / ≤14 / 更远）
  乘出饱和×不透明度 **100 / 92 / 85 / 75 / 65%**——任务在基色（黄/深黄/橙红）之上
  衰减，点子从纯白向灰白淡出。网格纵轴因此获得统一语义：**越往下离当下越远、
  越不需要马上关注**。
- **复选框（D12）**：任务便签左上角 18px 圆角方框 ☐（1.5px 描边 `#98A1A9`、白底）；
  完成/展开选中 = 品牌蓝底白勾 ☑；**点子无复选框**。
- **卡片内容**：折叠态（任务）= 复选框 + 正文首行标题（nowrap+ellipsis）+ meta；
  折叠态（点子）= 正文摘要 4 行截断；展开态 = 全文 + meta + 动作行。
  meta = 时间胶囊（仅带提醒的，D13）+ 右对齐弱化相对时间（「3 分钟前」）。
- **提醒胶囊格式**：`今天 14:30` → `周三 09:00`（7 天内）→ `9月20日 09:00`（更远）；
  全天显示 `全天 · 9月15日`。**过期徽标（D16）**：不划线不置灰，底色变浅橙红 +
  该轮未确认 = 「已到点」闪烁徽标（`prefers-reduced-motion` 只保留颜色）；
  已确认仍过期 = 灰橙「已过期」安静徽标，直到解决（完成 / 改期 / 关提醒 / 删除）。
- **完成态（D2，v2.4）**：入「已完成」折叠区——正文 line-through、整卡
  `opacity: .55`、复选框 ☑、胶囊隐藏、页脚「已完成」灰字；可随时恢复或清除。
- **Pin（D10）**：pinned 排序置顶 + 标题行一枚 14px 图钉小图标（仅标记，不改其他视觉）。
- 交互：点击卡片 = 折叠/展开（复用 cards，同时只一张）；复选框点击 = 完成/恢复
  （不触发展开）；动作行 = 编辑（弹窗）/ 钉住 / 删除（二次确认）。

## 四、便签编辑弹窗（新建 = 编辑）

- 入口（D20）：FAB 菜单「记任务 / 记点子」→ 打开弹窗并预选类型；
  点展开态「编辑」动作同样进入。
- 字段：
  1. **类型**：`任务 / 点子` 两段单选（默认任务）。任务 → 展开提醒区（可选开关）；
     点子 → 无提醒区；**点子 + 设提醒 = 类型迁移**（idea → task，单向，二次确认）；
  2. 正文 textarea（1–500 字，trim 后非空，计数显示）；
  3. **提醒开关（仅任务）**（D17/D18/D19）：
     - 模式二选一：**指定时间**（`date` + `time` 两个原生控件，分钟精度，移动端
       拉起系统选择器）/ **全天**（只选 `date`）；
     - **无快捷时间 chips**，日期时间完全由用户自行配置（D19）；
     - 重复：`不重复 / 每天 / 每周 / 每月 / 每年 / 每隔 N 天` 胶囊单选，默认不重复；
       选「每隔 N 天」出现 N 步进器（1–365）；
  4. ~~颜色~~：**移除取色器**（D21，颜色由类型 + 紧迫度派生）；
  5. 编辑态附加动作：「标记完成 / 恢复为未完成」（仅任务）「钉住 / 取消钉住」
     文字钮、「删除」（红色文字链，二次确认弹窗）；
  6. 保存 / 取消；保存时 diff-only 提交（见七）。
- 关闭提醒 = 提醒开关关（清空 `remind_at` / `repeat_rule` / `all_day`，显式传
  null，禁止用缺省表达清空），便签仍为任务。
- 弹窗底部 meta 行（D13）：带提醒的任务显示 `开始 · 9月12日 14:32` +
  `3 分钟前更新`；其余只显示 `3 分钟前更新`（不显示时间）。
- **通知权限 JIT**：用户第一次保存带提醒的便签时才申请 Notification 权限
  （just-in-time，不在页面加载时打扰）；被拒绝则只做站内提醒，不反复打扰。

## 五、提醒系统（核心）

### 5.1 触发循环（前端调度器）

- store 维护「下一次到点时刻」（仅 status=active 且 kind=task 且有 remind_at 参与
  计算）：指定时间 = `remind_at` 本身；**全天 = 当天 00:00**（D17）。
  `setTimeout(至该时刻)` 精确唤醒；**兜底每 30s 巡检**一次（防时钟休眠/轮询刷新
  导致计划漂移）；`visibilitychange` 回焦立即巡检。
- 到点判定：`到点时刻 <= now` 且 `last_fired_at < 到点时刻`——**全天提醒在当天
  任何时刻进入都判定为到点**（当日首次进站/轮询/巡检命中即触发，当日仅一次，
  由 `last_fired_at` 保证）。触发时**先本地写 `last_fired_at = now`**（V2 幂等键
  从 V1 起就有真实数据，见附录 A）并执行：
  1. **站内提醒卡**（顶部居中，z-index 1020，**不自动消失**，必须用户动作）：
     正文 + 时间 + 三个动作——**「知道了」**（确认）/ **「稍后提醒」**（+10 分钟）/
     **「打开」**（进编辑弹窗）；同时多条到点时聚合为「N 条到点」，逐条动作 +
     「全部知道了」；
  2. **浏览器系统通知**（点击通知聚焦本 tab）；
  3. **提示音**：WebAudio 两音清脆短音，无音频资产依赖；随头部静音开关关闭。
- **多标签页去重**：系统通知发出前查 localStorage `notes-fired`
  （`noteId → 触发时刻`，10 分钟窗口），本 tab 未见过该 id 才发系统通知；
  站内提醒卡各 tab 独立显示（与 cards 多 tab 各自独立口径一致）。
- 确认 = PATCH `reminded_at = now`；重复便签在确认时推进下一次（5.3）。未确认期间
  便签保持「到点未确认」醒目态，不会静默溜走。

### 5.2 错过的提醒（页面没开时到点）

- **过期派生态（D11）**：`viewStatus(note, now)` 纯函数——`done → 完成`；
  `active 且 remind_at <= now → 过期`；否则 `→ 正常`。过期不落库（六）。
  **全天口径**：全天提醒当天内不算过期，**从次日 00:00 起算**（当天未确认只是
  「已触发未确认」）。
- 进站/每次轮询合入数据后，凡**过期且该轮未确认**（`reminded_at < remind_at`）的，进
  **错过提醒条**（二.2），网格内排序置前 + 底色橙红；**不补发系统通知、不响铃**——
  补响会变成打开页面就被轰炸，违背 D1 的轻量定位。
- 用户逐条「知道了」/「全部知道了」后：`reminded_at = now`。重复便签推进到下一次
  未来时刻（5.3）→ 自然回到「正常」；**一次性便签** `remind_at` 仍是过去时刻 →
  警示消但标签保持「已过期」，直到解决（完成 / 改期 / 关提醒 / 删除）。

### 5.3 重复推进算法（`shared/notesDomain.js` 纯函数，可测）

```
advance(remind_at, rule, n, now):
  next = remind_at
  while next <= now:
    daily        : next += 1 天
    weekly       : next += 7 天
    every_n_days : next += n 天
    monthly      : next = 下个月同日，月末钳制（1月31 → 2月28/29）
    yearly       : next = 下一年同月日（2月29 → 2月28）
  return next   // 循环上限 1 万次，防脏数据死循环
```

- 触发/错过后**不立即推进**，等用户确认（知道了/打开/勾完成）时推进。
- 「稍后提醒」：`remind_at = now + 10min`（保留 repeat_rule）；重复便签贪睡后
  以下一次确认为推进基点，允许小幅基点漂移（可接受，记录在此）。
- 该函数自 v2 起放 `shared/`，V2 Cron Worker import 同一实现（〇.2.4）。

### 5.4 完成与提醒交叉（D8）

- status=done 的便签**不参与调度、不进错过条**；「标记完成」若当次已到点未确认，
  一次 PATCH 同时写 `status='done'` + `reminded_at=now`。
- 重复便签被完成 = 整个循环终止（不再推进）；「恢复为未完成」不回溯任何提醒，
  恢复后若 `remind_at` 已成过去时，走 5.2 错过条（不补铃）。

### 5.5 时区与精度

- `remind_at` 落库 `timestamptz`，客户端用本地时区写入/展示；多端各自本地渲染，
  不存在跨时区换算争议。分钟精度 = `datetime-local` 原生保证。

## 六、数据模型（supabase/notes.sql，风格对照 cards.sql）

```sql
create table public.notes (
  id              uuid primary key default gen_random_uuid(),
  user_id         uuid not null references auth.users(id) on delete cascade,
  kind            text not null default 'task' check (kind in ('task','idea')),  -- D14/D20：任务=task（含带/不带提醒），点子=idea
  content         text not null check (trim(content) <> '' and char_length(content) <= 500),
  status          text not null default 'active' check (status in ('active','done')),
  pinned          boolean not null default false,       -- 钉住（D10）：置顶/清除保护
  remind_at       timestamptz,                          -- null = 无提醒；全天 = 当天 00:00（本地）
  all_day         boolean not null default false,       -- D17：全天提醒
  repeat_rule     text not null default 'none'
                  check (repeat_rule in ('none','daily','weekly','monthly','yearly','every_n_days')),
  repeat_interval int not null default 1
                  check (repeat_interval between 1 and 365),  -- every_n_days 的 N
  last_fired_at   timestamptz,                          -- 最近一次触发/派发时刻（V2 幂等键，V1 前端触发即写）
  reminded_at     timestamptz,                          -- 最近一次用户确认时刻
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now(),
  check (kind <> 'idea' or remind_at is null)           -- D14：点子禁止带提醒，DB 兜底
);
alter table public.notes enable row level security;
create policy notes_owner on public.notes
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
create index notes_user_list on public.notes (user_id, status);
create index notes_remind_scan on public.notes (remind_at)
  where remind_at is not null and status = 'active';  -- V2 cron 全表按时刻扫描（〇.2.5）
```

- **顺序、颜色都不落库（v2.4）**：排列是纯派生（D4：pinned → 开始时间 → 已完成区），
  无 `sort_order`、无拖拽调序接口；底色由类型 + 紧迫度派生（D21），`color` 列移除
  ——记录的顺序和颜色都由数据本身决定，与余额表「样式随数值变化」同一哲学。
- **点子约束落库**：`kind='idea' ⇒ remind_at is null` 由 CHECK 兜底（D14），
  杜绝「点子带提醒」的脏状态；「带提醒 / 纯备忘」由 remind_at 是否为 null 派生，
  无需单独字段。
- `updated_at` 由触发器维护，冲突语义 = **后写覆盖先写**（LWW，与 cards 同口径）。
- **过期不落库**：`过期`是时间派生态（D11/D16，viewStatus 纯函数）——时间自己
  能算出来的，绝不存一份会过期的副本。
- 每用户上限 **200 条**（API 层校验，防板子无限膨胀）。

## 七、API 契约（functions/api/notes.js + functions/api/notes/[id].js）

沿用 cards 的中间层模式：`_middleware.js` 已验签并把 access token 放进 `data`，
本层只做白名单/枚举/长度校验，RLS 兜底数据归属。

| 方法 | 路径 | 语义 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/notes` | 全量拉取（≤200 条，排序/过滤/底色档全在前端派生） | 行数组 |
| POST | `/api/notes` | 新建（类型/内容/提醒） | `Prefer: return=representation` 单行 |
| PATCH | `/api/notes/:id` | **diff-only** 部分更新（编辑/确认/贪睡/推进/完成/钉住） | 单行 |
| DELETE | `/api/notes/:id` | 撕掉 | 204 |

- PATCH 提交契约沿用 cards：**只传变化字段**，未携带字段保留现值（关闭提醒这类
  「清空」必须显式传 null，禁止用缺省表达清空）。
- PATCH 字段白名单：`kind / content / status / pinned / remind_at / all_day /
  repeat_rule / repeat_interval / reminded_at / last_fired_at`。
- 校验：content 1–500 trim；kind、repeat_rule、status 枚举；pinned、all_day
  布尔；repeat_interval 1–365；`kind='idea' ⇒ remind_at is null`
  （与 CHECK 同口径）；
  remind_at 可解析 ISO 时间戳（**允许过去时刻**——重复推进由 5.3 处理；
  一次性规则下贴一张「已经错过的备忘」也是合法输入，落站后走错过条）。
- POST 时该用户 notes 计数 ≥ 200 → 409。

### 8.1 同步与乐观更新（D5）

- **进站**：先渲染 localStorage 快照 `notes-snapshot-v1`（rows + fetched_at，
  超 7 天弃用）实现秒开，随后 GET 全量合入并刷新快照。
- 此后**页面可见时每 45s 轮询**（`visibilitychange` 隐藏即停，回焦立即拉一次）
  ——同口径 cards 会话控制器。
- 用户操作（新建/编辑/删除/确认/完成/钉住）= **本地先改 + 单请求**，响应以
  `return=representation` 回写，不二次拉列表（对照 cards 请求预算）；请求失败
  toast 报错、本地保留不回滚（不建离线队列，V1 取舍，见九.9）。
- **全量展示（v2.4，D15 窗口废止）**：便签一次全量拉取（≤200 条），排序/筛选
  （全部/任务/点子）/底色档全部在纯函数层派生，切换零请求——对齐余额 0 余额
  开关的本地过滤模式。
- **同步状态点**：`同步中`（请求未归）/ `已同步`（最近成功 < 90s）/ `离线`
  （失败，点击重试）——「多端同步」是卖点，必须可感知，不能只是后台噪音。

### 8.2 排列与折叠展开（D4/D12，v2.4）

- 排列纯函数 `listOrder()`：pinned → `abs(distanceDays())` 升序（同距离按精确
  时刻贴近今天者优先）；已完成不入主流网格，进「已完成」折叠区。
- 距离/衰减纯函数：`distanceDays()`（任务 = remind_at，全天取当天 00:00；
  点子与无提醒任务 = created_at）与 `fadeLevel()`（D22 五档），衰减作用于
  卡片容器（filter: saturate + opacity），展开态仍保底 65% 可读性。
- 折叠/展开复用 cards 行为：同时只一张展开、跳 z 1000、
  `scrollIntoView({ block: 'center' })`、再点收起；瀑布流 = CSS multi-column，
  展开是卡内增高、不跨列。
- 复选框点击 = 完成/恢复（一次 PATCH `{status}`），完成后卡片飞入已完成区
  （220ms）；在已完成区恢复则飞回主流网格。

### 8.3 筛选与已完成区（D20/D2，v2.4）

- 筛选纯函数 `filterByTab(rows, tab)`：全部（混排）/ 任务（kind=task）/
  点子（kind=idea）——默认全部，切换零请求。
- 已完成区 = `rows.filter(status === 'done')`，折叠栏显示计数；「清除已完成」=
  逐条 DELETE（跳过 pinned），二次确认。

### 8.4 提醒调度器（见 5.1，实现位在 store）

- store 持有最近 remind_at，`setTimeout` 精确触发 + 30s 兜底巡检；
  触发即写 `last_fired_at` 并入「到点队列」驱动提醒卡；确认/贪睡/推进/完成
  各是一次 PATCH。

### 8.5 动作入口（D12，v2.4）

- **复选框**（任务卡左上角）：点 = 完成/恢复，一次 PATCH `{status}`（D8 交叉
  语义照旧：完成隐含确认当次到点）；不触发展开。
- **卡片点击** = 折叠/展开；展开态动作行：编辑（弹窗）/ 钉住 / 删除（二次确认）。
- Pin/取消 = 一次 PATCH `{pinned}`。

## 九、边界与已知取舍（记录，不阻塞）

1. **贪睡导致重复基点漂移**：见 5.3，接受。
2. **全量展示后网格会变长**：便签上限 200 条 + 已完成折叠区兜底；将来量大再引入
   归档/分页（对齐余额表「历史保留」的处置节奏）。
3. **紧迫度色档的边界**：≤24h 深黄按「距开始时刻」计算（全天按当天 00:00）；
   跨零点自然换档，无过渡动画。
4. **系统通知依赖权限与浏览器策略**：iOS Safari 需添加到主屏幕才支持通知
   ——站内提醒卡永远是主通道，系统通知是增强。
5. **页面休眠（笔记本合盖）**：回来时走 5.2 错过提醒条，不补铃。
6. **后台标签页节流**：Chrome 对后台 tab 定时器钳到 ≥ 1 次/分钟——对「分钟精度」
   恰好够用；30s 兜底 + 回焦巡检双保险。
7. **本地时钟漂移不做校准**：V1.1 可用响应 `Date` 头估算偏移后再议。
8. **45s 轮询窗口内他端改动延迟可见**：便签不是聊天，回焦即拉已覆盖绝大多数场景。
9. **恢复已完成便签**：不回溯任何提醒；过去时 remind_at 走错过条（5.4）。
10. **Pin 与批量清除**：「清除已完成」跳过 pinned 便签；想清掉 pinned+done 的，
    先取消 Pin。
11. **标签页懒加载与提醒调度**：用户停在别的标签时便签调度器不运行——到点提醒
    只在便签标签激活（或 Hello 页可见）期间响；切回时走错过条口径（5.2）。
    这是标签页集成的固有取舍，V2 服务端推送补齐（附录 A）。
12. **瀑布流顺序**：CSS multi-column 按列填充，阅读顺序「先列后行」与排序语义
    略有出入——记录场景可接受；追求严格行序时换 grid + row span（V1.1 备选）。
13. **点子默认展开的空间开销**：点子多时网格被撑长；展开摘要截断 4 行兜底，
    点开仍看全文。
14. **距离并列决胜**：同距离（同一天到期/同一天创建）按精确时刻到今天的间隔
    秒数升序，仍并列按创建时间新者在前——保证排序全序、渲染稳定。
15. **衰减与过期色的叠加**：过期橙红卡若同时久远（理论上少见），衰减照乘——
    颜色语义（类型/紧迫度）与强度语义（距离）正交，各自独立计算。

## 附录 A · V2 服务端提醒方案（本版成文，暂不实施）

### A.1 载体：独立 Cron Worker

- **Cloudflare Pages Functions 不支持 cron triggers**，且项目保持 Pages 托管不变
  → V2 新增**独立 Worker**：仓库内 `cron-worker/` 目录（独立 `wrangler.toml`，
  `triggers.crons = ["* * * * *"]`，`wrangler deploy` 单独发布），与前端零耦合。
- Worker 用 `SUPABASE_SERVICE_ROLE_KEY` 裸 fetch PostgREST（平台「无 SDK」风格不变），
  直接 `import shared/notesDomain.js` 复用 `advance()`。

### A.2 扫描与幂等

```
每分钟：
  select * from notes
    where status='active' and remind_at <= now()
      and (last_fired_at is null or last_fired_at < remind_at)
  → 逐条派发（A.3）
  → last_fired_at = now()
  → daily/weekly: remind_at = advance(remind_at, rule, now)   -- Worker 负责推进
  → none: 保持过去时刻，等待用户确认（与 V1 语义一致）
```

- 幂等键 = `last_fired_at < remind_at`：V2 上线后 Worker 与 V1 前端调度器
  **同时存在也安全**（谁先处理谁写入，另一方自然跳过）；上线后「确认时推进」
  的推进主体改归 Worker，前端确认只写 `reminded_at`。
- 扫描索引已就位：`notes_remind_scan`（六）。

### A.3 渠道

1. **Web Push**（主渠道）：
   - 前端注册 `/sw.js`（`push` 事件 → `showNotification`；`notificationclick` →
     focus / open `/app/notes`）；便签墙头部「通知设置」小弹窗内一键订阅
     （PushManager + VAPID 公钥），可退订与发测试推送。
   - `push_subscriptions` 表：`user_id / endpoint(unique) / p256dh / auth /
     user_agent / created_at`，RLS owner policy。
   - Worker 端 `cron-worker/lib/webpush.js`：Web Crypto 签 VAPID JWT +
     RFC 8291 加密 payload，零 SDK；endpoint 返回 404/410 时删行清理。
2. **邮件**（可选、默认关）：Resend API 发「便签墙提醒」到注册邮箱；
   用户设置里开启，V2.1 再议。

### A.4 约束与风险

- **iOS Safari**：需先「添加到主屏幕」（manifest + SW 就绪后可用），页面内做引导文案。
- **Workers 免费额度**：每分钟 cron ≈ 1440 次/天，远低于免费请求额度；
  部分索引空扫成本可忽略。
- **免打扰时段 / 提前量**（如提前 5 分钟）：V2.1 设计，本版不落库。
- **全天提醒的服务端推送**：推送时刻（如用户本地 09:00，存储仍为当天 00:00）
  与免打扰时段一并留 V2.1 细化；V2 先只对「指定时间」提醒走服务端渠道。
