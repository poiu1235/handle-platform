## 一、产品定位

**做准确的提醒服务，只基于当下。**

一个被动的提醒型网站：用户点开来看，所有付费项目"当下"的有效期、剩余次数、
续费扣款日集中清晰呈现；处于提醒窗口内的卡，进站即 alert 警告。

- 不主动推送（预留二期）；提醒只发生在进站后。
- 不碰钱、不算花销；不管使用规则；不记历史。
- 数据主权在外部自动化工具；用户日常动作是"看 + 被提醒"。

三条价值：**集中梳理**（一张清单看清所有付费项目）、**到期不浪费**（提前 15 天）、
**扣款不意外**（提前 7 天）。

## 二、核心原则：只存当下，不存历史

- 每个「商户 - 卡种」**有且只有一条记录**，永远是最新状态；所有写入**直接覆盖**，
  不保留版本、世代、流水。
- 产品只回答四个当下问题：这张卡**还剩多少天、还剩多少次、下次什么时候扣费、
  扣费之后的套餐 DDL 是什么**（最后一样由 DDL + 扣款周期推导展示，不存字段）。
- **不留过程数据**：过去买过几次、买了多久、历史续卡开卡情况、旧卡世代、每次核销的日期——
  一概不做。核销 / 打卡记录在商户自己的 App 后台可查，提醒服务不重复建设。
- **唯一的例外元数据**：关键字段（终止日期 / 剩余次数 / 下次扣款日 / 自动续费标志）
  各记录**最后一次写入的来源**（导入 / 手动）。每字段一个标记，是第八节冲突检测的机制，
  不是历史。

## 三、产品形态

- **网站，被动形态**；提醒为**窗口制**：15 天 / 7 天是窗口起点，窗口内任何时候进站都会看到。
- **数据主权在外部**：批量录入 + 单条添加两个入口，同名（卡名 + 商户）upsert，
  写入即覆盖为最新状态。
- **用户操作全集**（只有这 8 个）：
  1. 看清单 / 看卡片详情
  2. 处理进站提醒：忽略 / 本周期不提醒 / 永远静默（按卡设置）
  3. 手动顺延：修改终止日期（不能早于今天；自动续费卡须先关自动续费，见 6.2）
  4. 修改剩余次数
  5. 标记已使用完（仅带次数的卡；本质是"剩余次数清零"的快捷方式，见第七节）
  6. 删卡（记录整个消失，唯一不可逆操作，有确认弹窗）
  7. 开 / 关自动续费；自动续费卡可修改扣款日
  8. 批量录入 / 单条添加

  **没有「标记已过期」**：过期 = 今天已超过终止日期，是日期推导出的自然状态。
  想让卡"别过期"就去顺延 DDL；想让卡消失就删卡。

## 四、一张卡记录什么（概念模型，非库表）

| 组 | 字段 | 说明 |
| --- | --- | --- |
| 身份 | 卡名、商户/门店、分类 | 分类：健身/洗车/理发/按摩/瑜伽/美甲/影音会员/其他 |
| 有效期 | 起始日期、终止日期（DDL） | **核心字段**。起始日期规则见下；DDL 手动改时不能早于今天；无限期默认 = 起始 + 1 年 |
| 用量（可选） | 剩余次数（可带套餐总量） | 只记次数不记时长；仅带此字段的卡才有"已用完"状态 |
| 续费（**必选标志**） | 是否自动续费，默认关 | 开启则必填：扣款周期、下次扣款日（默认 = 当前 DDL 往后延续）；只有自动续费卡有扣款日、才可改 |
| 元数据 | 各关键字段最后写入来源 | 导入 / 手动；仅此一项"类历史"数据，服务冲突检测 |

**起始日期规则**：

- 录入后**不可修改**（单条、批量一视同仁）。
- **单条添加**：起始日 = 当天（当天激活），不提供历史日期选项。
- **批量导入**：允许历史起始日，**最早 3 个月前**；更早的按行报错。
- 基础校验：DDL ≥ 起始日期；批量导入允许录入已过期的卡（自然沉底展示，不提醒）。

- 混合卡 = 两张独立卡；储值类归「余额」模块（本金/赠金区分另行立项）。

## 五、提醒逻辑（两类窗口并存 + 静默）

| 提醒 | 适用卡 | 窗口 |
| --- | --- | --- |
| 快到期 | **所有卡** | 终止日期前 **15 天**起 |
| 快扣款 | **自动续费卡（额外）** | 下次扣款日前 **7 天**起 |

- 自动续费卡可能同时命中两类（DDL ≈ 下次扣款日）：alert 合并为一条、标注全部原因。
- 窗口内每次进站都 alert；窗口自然结束：过期（不提醒了）/ 扣款完成（顺延）/ 用户处理 / 静默。
- **静默（按卡）**：「本周期不提醒」（到下次顺延 / 周期更替为止）、「永远静默」。
  静默只是不提醒——时间照走、状态照常推导、自动续费循环照跑、卡正常留在清单里。
  **删卡才是让记录彻底消失**（列表里都找不到）。
- 已过期、已用完的卡不 alert（灰卡沉底）；剩余次数多少不进提醒。
- 渠道仅进站 alert；push / 邮件 / 日历预留二期。

## 六、生命周期与状态

### 6.1 状态推导（全部由数据推导，无人工状态）

```
已删除   —— 记录不存在（不可逆）
已过期   —— 今天 > 终止日期；灰卡沉底，不 alert          【优先级高】
已用完   —— 带次数的卡 且 剩余次数 = 0；灰卡沉底，不 alert 【优先级低；无次数字段的卡不存在此状态】
生效中   —— 其余；处于提醒窗口内叠加「即将到期 / 即将扣款」角标
```

- 顺延在下次进站 / 导入结算时生效（产品无后台定时任务）：自动续费卡的 DDL 刚过、
  尚未进站的短暂窗口里，卡先显示为已过期，结算顺延后恢复生效中。

### 6.2 自动续费循环（忽略即续）

```
扣款窗口（T-7 天）内进站 → alert
  ├─ 用户打断（直接动作仅 3 个）：取消自动续费 / 标记已使用完 / 删卡
  └─ 用户忽略（或整个窗口没打开网站）→ 默许续费
        → 扣款日后自动顺延一个周期：
          DDL 与下次扣款日各 +1 周期（保持两者相对关系）、次数卡剩余次数重置为套餐次数
        → 进入下一个提醒窗口，循环继续
```

- 手动顺延对自动续费卡不可直接操作：先关闭自动续费 → 卡变回普通期限卡 → 手动顺延 →
  还想要自动续费的话，再主动打开按钮**重新设置**（周期 + 下次扣款日）。
- 单独修改扣款日不影响 DDL（两者独立）；只有顺延才同时推进两者。
- 顺延重置次数后若与外部数据源有差异：后续重新扫描导入或手动修改都可直接更正。
- 取消自动续费后：回到普通期限卡逻辑，DDL 固定、自然走到过期；到期提醒照常适用。

## 七、终结与恢复（状态单一来源）

**原则：状态全部推导，不存在独立的"标记状态"，因此不需要"取消标记"操作——
把数据改回去，状态自然回来。**

- **已用完（仅带次数的卡）**：「标记已使用完」= 剩余次数清零的快捷编辑。
  恢复 = 手动改回次数，或导入确认（外部数据 count > 0）。
- **已过期**：恢复 = 手动顺延 DDL（≥ 今天），或导入带来未来的 DDL（确认后生效）。
  自动续费卡的恢复：重新打开自动续费并设置，或先关续费再手动顺延。
- 恢复后状态立即重新推导为生效中，零额外步骤；不保留任何过程痕迹（只存当下）。

## 八、导入冲突与逐条确认

### 8.1 导入流水线

```
解析 → 逐行分类：
  ① 新增         库内无同名卡 → 直接进预览
  ② 自然更新     变化属于"推进"且不覆盖手动值 → 静默落库
  ③ 冲突（需确认）覆盖手动设置的值 / 数据倒退 / 卡复活 → 新旧对照，逐条确认
  ④ 格式错误     解析失败（含起始日期早于 3 个月前）→ 逐行报错
提交 = ①② 落库 + ③ 中已确认行落库；未确认行保留旧值
```

### 8.2 冲突判定（③）

- **覆盖手动值**：字段旧值来源为「手动」而导入要改 → 冲突；
  旧值来源为「导入」或「自动顺延」→ 自然更新，静默落库（外部工具是数据主权方）。
- **无条件冲突（无论来源）**：终止日期从未来改为过去（生效卡直接判死，可能是扫描错误）；
  自动续费标志翻转（开 ⇄ 关）；**卡复活**（库内已过期 / 已用完，导入数据显示仍有效）。

### 8.3 确认交互与未采纳处理

- 每条冲突展示「字段 | 旧值（来源） | 新值（导入）」，逐条**采纳 / 保留旧值**，
  提供「全部采纳」快捷操作。
- 未处理的冲突行**默认保留旧值、不落库、不留"待处理"队列**——外部工具下次扫描会带来
  同样的新值，冲突自然重现。
- 确认采纳后：新值直接覆盖落库、来源标记改为「导入」、状态立即重新推导。
- 同批次内同名：按顺序后写覆盖先写，预览合并为一条，不重复确认。

## 九、明确不做

不算钱、不算花销；不做打卡 / 签到 / 核销按钮；不做使用规则（单日限用、停卡顺延）；
不记时长；不设独立"取消截止提醒"；不依赖用户日常管理；
**不保留任何历史**（续费/开卡/购买历程、旧卡世代、核销/打卡流水——商户 App 后台可查，不重复建设）。

## 十、二期占位

1. 打卡 / 使用频率提醒（"这个月只用了 1 次，要不要别续了"）。
2. 强提醒渠道：push / 邮件 / 日历订阅。
3. 余额模块 · 本金与赠金区分（属余额模块）。

## 十一、全流程总览（一屏读懂）

```
创建   单条添加 = 当天激活（起始日固定今天）
       批量导入 = 可回填历史起始日（最早 3 个月前），写入即覆盖
   ↓
生效中  清单正常展示；进入提醒窗口
       （到期前 15 天 · 所有卡 ／ 扣款前 7 天 · 自动续费卡）→ 进站 alert
   ├─ 忽略 ──→ 自动续费卡：扣款日后默许顺延（DDL/扣款日 +1 周期、次数重置）→ 循环继续
   │           非自动续费卡：自然走到过期
   ├─ 打断 ──→ 取消自动续费（变普通期限卡）/ 标记已使用完（次数清零）/ 删卡（消失）
   └─ 静默 ──→ 本周期不提醒 / 永远静默（只是不吵，循环照跑、状态照常）
   ↓
终结   已过期（今天 > DDL）/ 已用完（次数 = 0）→ 灰卡沉底、不提醒
   ↓
恢复   顺延 DDL / 改回次数 / 导入确认复活 → 状态立即重新推导为生效中
```

数据侧一句话：**一条卡记录 + 关键字段来源标记；写入即覆盖；无历史。**
